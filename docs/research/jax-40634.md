# Historical regression replay: JAX #40634

XLAxiom uses the trusted in-package adapter `jax-40634-asinh-acosh-large-float32-v1`; the corpus record itself is data and cannot execute arbitrary Python.

## Verified upstream context

The [original issue](https://github.com/jax-ml/jax/issues/40634) reports that the float32 JVP rules for `arcsinh` and `arccosh` squared a large input before reciprocal square root. At `1e22`, the square overflows while the mathematically correct derivative (`1 / hypot(1, x)`) remains representable at about `1e-22`. The issue records JAX 0.11.1 and shows both gradients as zero. The upstream [fix commit](https://github.com/jax-ml/jax/commit/86d3fe7) changes the `arcsinh` JVP and adds a regression test; the issue states that the behavior was fixed at then-current head.

## Local replay, 2026-10-12
